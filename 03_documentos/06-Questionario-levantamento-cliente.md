# Guias rápidos para localizar as informações

## Passo a passo A — Ver o projeto e o link no Asana

1. Entre no Asana com sua conta normal.
2. Abra um projeto que possa entrar no piloto.
3. Copie o endereço da página do projeto (URL do navegador). Envie o link e o código/nome que sua equipe usa.
4. Se houver projetos parecidos, confirme qual equipe ou portfólio deve entrar. Não convide pessoas nem altere o projeto para responder.

## Passo a passo B — Ver campos, opções e tarefas sem mudar nada

1. Abra o projeto no computador e escolha a visualização Lista ou Quadro.
2. Anote os nomes das seções/colunas (por exemplo, “Em andamento” ou “Entregue”); isso costuma representar a etapa de uma tarefa.
3. Clique em “Personalizar” (Customize) > “Campos” (Fields). Anote o nome de cada campo que acompanha fase, cliente, responsável, datas ou status legal.
4. Para campos de lista suspensa, abra uma tarefa de exemplo e anote o valor selecionado e as opções disponíveis. Não altere nem salve nenhum valor.
5. Abra a aba “Visão geral” (Overview). Veja o indicador de saúde do projeto e as atualizações anteriores. Ele é diferente das seções das tarefas e dos campos legais.
6. Envie nomes e opções ou, se autorizado, use o passo C para exportar uma amostra.

## Passo a passo C — Exportar uma amostra do projeto

1. No cabeçalho do projeto, clique na seta/menu ao lado do nome.
2. Escolha “Exportar/Imprimir” (Export/Print) e depois CSV ou JSON.
3. Selecione apenas um projeto aprovado para amostra. Confira o arquivo antes de compartilhar e remova dados pessoais que não sejam necessários.
4. Coloque o arquivo na pasta segura que a equipe indicar; não envie por WhatsApp aberto. A exportação é opcional: links e nomes dos campos podem bastar.

## Passo a passo D — Conferir pelo API Explorer do Asana

Use isto apenas se alguém da equipe se sentir confortável. Os endereços são requisições GET (leitura); não clique em ações POST, PUT, PATCH ou DELETE.

1. Abra a referência oficial da API Asana e localize “Get workspaces”. Clique em “Try it”. Autorize sua conta se o Asana pedir.
2. Na resposta, encontre `data` e anote somente o nome do workspace e seu `gid` (identificador). O endpoint de referência também é `GET https://app.asana.com/api/1.0/workspaces`.
3. Abra “Get projects”/“Get projects in a workspace” e informe o workspace GID. Anote os GIDs e nomes dos projetos-piloto.
4. Para um projeto, consulte `GET /projects/{project_gid}` e `GET /projects/{project_gid}/tasks`. Use `limit=100` e, se a resposta trouxer `next_page`, continue pela próxima página.
5. Para campos personalizados, confira o nome, o tipo (texto, número, data, seleção) e as opções. Se o API Explorer retornar `403`, não tente ampliar permissões sozinho; anote a mensagem e envie para a equipe técnica.
6. Para as atualizações de status do projeto, prefira a API atual `GET /status_updates?parent={project_gid}` quando disponível. Rotas antigas `project_statuses` são marcadas como depreciadas na referência.
7. Envie apenas workspace GID, project GIDs, nomes de campos/opções e mensagens de erro sem dados pessoais. **Nunca copie o token ou cabeçalho Authorization para um arquivo/chat.**

## Passo a passo E — API para teste e conexão segura

Para um teste curto, o Asana permite criar um Personal Access Token (PAT) na Developer Console: no Asana clique na foto do perfil > Configurações (Settings) > Apps > Gerenciar/Ver Developer Console; escolha “Create new token”, dê um nome para o teste e armazene o token em local seguro. O token aparece uma vez e funciona como senha daquela conta. A pessoa que o criou deve revogá-lo depois do teste.

**Não envie esse PAT à Adapta por WhatsApp/e-mail/este documento.** Se for necessário um teste técnico, combine uma sessão segura para a própria pessoa autorizada inserir o token em um cofre/ambiente aprovado. O PAT é apenas para uma verificação curta; a pessoa que o criou deve revogá-lo após o teste.

**Para a integração de produção (OAuth), faça estes passos quando a equipe técnica fornecer o endereço de retorno (redirect URL):**
1. Na Developer Console, escolha “Create new app”. Dê um nome identificável, por exemplo “Thórus — Gestão de Projetos”.
2. Abra as informações/OAuth do app. Cole o redirect URL HTTPS exatamente como a equipe técnica enviar. Não invente nem ajuste o endereço.
3. Em OAuth > Permission Scopes, habilite somente os acessos aprovados para o piloto: leitura de workspaces, projetos e tarefas; custom fields/usuários apenas se a equipe confirmar que são necessários. Não selecione “Full permissions”, escrita ou exclusão.
4. Em Manage distribution, libere o app apenas para o workspace da Thórus. Salve.
5. Envie o nome do app e o Client ID (identificador público) à equipe pelo canal de projeto. O Client Secret é segredo: a equipe técnica deve guardá-lo no cofre/secret manager, nunca em mensagem, documento ou código.
6. Quando a conexão estiver preparada, abra o sistema e use “Conectar Asana”. O administrador entra no Asana e autoriza o app pela tela oficial. O token fica no servidor da aplicação; não é copiado pelo usuário.

2. Verifique se o evento contém um link ou documento de notas/resumo do Gemini/Meet.
